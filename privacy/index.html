1. Core Philosophy

Your side of the day.
Nothing more, nothing less.

Monolog is built by NoTokens Co. as an Android-first AI keyboard and private personal journal. Most software treats personal typing as telemetry or training data. Monolog rejects this model entirely.

Our architecture is governed by three foundational technical principles:

  • Familiar first, private always: Everyday typing must be instantaneous, reliable, and decoupled from any network requirement. If all network connections are severed, Monolog remains a completely functional, private keyboard.
  • Separation of evidence from interpretation: Typing “meeting Sam at 5 PM” is evidence of a draft or plan—not proof that a meeting occurred. Monolog does not infer other people’s feelings, actions, or incoming replies that it never observed.
  • Strict asymmetric boundary: As an Android Input Method Service (IMS), Monolog operates exclusively with the text you type or dictate. It has no technical access to incoming chat messages, read receipts, or other participants’ messages in third-party apps.

No Ad Networks. No Data Brokerage.

Monolog is funded by optional premium subscriptions (Monolog Pro), not by advertising or data monetization. We do not sell, license, rent, or trade your keystrokes, journals, or personal metadata to third parties.

Memory On — Consensual Encrypted Journaling

With explicit consent, eligible non-sensitive drafts contribute to your personal journal. Data is stored directly on your phone in an encrypted SQLite Room database secured by Android Keystore AES-256-GCM. On-device Gemma AI assists locally without silent uploads.

State Specifications

  1. Memory Off: Monolog functions strictly as an input method. No keystrokes are recorded in storage. The Room database remains closed. Local AI creates zero memories or timeline summaries. Explicit eligible queries (such as a dictionary lookup) operate ephemerally.
  2. Memory On: When explicitly enabled by the user during onboarding or in settings, eligible text segments pass through local privacy filters (stripping unrecognized tokens, credentials, and numbers matching credit card or OTP formats) before persistence into the encrypted SQLite Room database on your phone.
  3. Manual Incognito: Triggered by long-pressing the period key (.) or tapping Incognito in the keyboard menu. An active hat-and-glasses icon appears with a 15-minute countdown (configurable). During this window, memory capture and local learning are paused entirely.
  4. Automatic Protected Input (Banking & Sensitive Fields): Triggered automatically when Android reports input field types such as TYPE_TEXT_VARIATION_PASSWORD, TYPE_TEXT_VARIATION_VISIBLE_PASSWORD, TYPE_NUMBER_VARIATION_PASSWORD, or when typing inside user-excluded apps (such as banking or cryptocurrency wallets). This state cannot be overridden, cannot be turned off by the user, and does not expire on a timer. Predictions, personalized suggestions, voice input, screen capture, and cloud assistants are completely disabled.
3. Security Engineering

On-device cryptographic architecture.

Storing personal reflections requires military-grade data at rest protections. Monolog utilizes the Android Keystore system coupled with SQLite Room database encryption.

Android Keystore AES-256-GCM Hardware Isolation

Room alone is not encryption. Monolog binds its database encryption master key to the hardware-backed Android Keystore (utilizing ARM TrustZone / StrongBox Keymaster where supported). The cryptographic keys never enter user-space memory and cannot be extracted even if the file system is cloned.

Local Model Execution

Monolog deploys Google Gemma 2B via LiteRT-LM (TensorFlow Lite runtime) compiled specifically for on-device Neural Processing Units (Qualcomm Snapdragon NPU, Google Tensor TPU, MediaTek APU).

  • Zero Server Rerouting: Contextual suggestions, semantic search across personal memories, and timeline clustering are computed 100% locally on your hardware.
  • Thermal & Battery Safety: Local inference executes only during active idle charging or brief interactive bursts, preserving device battery life and temperature.
4. Audio & Screen Context

Vox voice mode & screen context.

Vox Voice Mode Privacy Rules

Vox is an integrated voice typing surface inside the keyboard toolbar. It operates under strict privacy safeguards:

  • Gesture Activation Only: Audio recording begins only when the user holds the microphone key or taps the Vox button. There is no passive background listening, no hotword detection engine (“Hey Monolog”), and no ambient sound buffering.
  • Truthful Waveform Feedback: The visual waveform animation maps strictly to genuine audio amplitude from the device microphone. If recording stops, the waveform freezes immediately.
  • Local Speech Recognition: Voice audio is converted to text using on-device ML Kit Speech Recognizer whenever supported by the Android system. Audio recordings are discarded immediately after transcription unless explicitly saved as an intentional voice note in your Context Library.
  • No Automatic Sending: Transcribed speech is presented in an editable preview strip. Monolog never dispatches a draft to the recipient app automatically.

Context Engine & Screen Capture (`m` Key)

The dedicated m key allows users to capture visual context into their searchable Context Library:

  • Explicit Permission per Capture: Screen capture uses the standard Android MediaProjection framework, requiring explicit runtime user permission before taking a screenshot. Monolog cannot take background screenshots.
  • Strict FLAG_SECURE Compliance: Monolog honors the Android WindowManager.LayoutParams.FLAG_SECURE flag. Applications that declare themselves secure (e.g. banking apps, password managers, private browser tabs) cannot be captured, and Monolog will not attempt to bypass this limitation.
  • In-Flight Redaction: When a screen is captured, an immediate preview editor appears allowing you to crop out sensitive sections, redact text, or delete the screenshot before saving.
5. Network & Cloud Boundaries

Explicit opt-in cloud AI logic.

While Monolog is on-device by default, select complex actions—such as web-grounded research or high-order rewriting—can utilize cloud intelligence. Cloud connectivity operates strictly under an explicit opt-in model.

Firebase AI Logic & Gemini 1.5 Flash

When you hold the lightning-marked spacebar to summon the Floating AI panel or select an advanced tone rewrite:

  • Minimal Payload Transmission: The network payload contains exclusively the exact text query you entered and any screenshot or attachment you manually chose to attach. It never transmits your broader journal, historical keystrokes, or background device state.
  • No Model Training: Under our enterprise terms with Google Cloud and Firebase AI Logic, customer queries sent via the Monolog API are not retained for training foundational AI models.
  • Search Isolation: When web searches are performed to retrieve cited facts, the search query and retrieved citations do not automatically become part of your personal journal unless you tap "Save to Journal".

Optional Google Drive Encrypted Backup

If you choose to enable cloud backup, your journal records and context media are encrypted client-side using a user-held passkey before transmission to your personal Google Drive storage. NoTokens never receives your backup data or encryption key.

7. Sovereignty & Control

Your rights & complete deletion.

You hold uncompromised sovereignty over your data. We provide granular controls within the Monolog application settings:

  • Inspect & Review: You can open the Journal Timeline and Context Library at any moment to view every recorded highlight, voice note, and extracted snippet.
  • Edit & Exclude: You can edit any AI-generated summary title, rewrite body text, or flag specific days/moments to be permanently excluded from monthly recaps.
  • Granular Deletion: Deleting an item immediately removes it from the local Room database, purges its associated file from local storage, and strips its vector embedding from local search indexes.
  • Data Portability: Export your complete journal timeline and Context Library in standard, non-proprietary formats (Markdown documents with accompanying media folders or structured JSON).
  • The "Forget Everything" Master Wipe: A single tap in Monolog Settings > Privacy triggers a cryptographic erasure. The Room database is dropped, local file caches are unlinked, and Android Keystore master keys are revoked, rendering any remnant data permanently undecryptable.

9. Transparent Answers

Frequently asked questions.

Why does Android display a warning when enabling Monolog as an IME? +

Android displays a standardized, non-customizable warning message for every third-party keyboard: “This input method may be able to collect all the text you type, including personal data like passwords and credit card numbers.”

This is a necessary platform security warning because Android keyboards operate with low-level input access. Monolog respects this trust by implementing strict on-device encryption, automatic password bypass, and an open, auditable privacy model.

Can Monolog see or log my banking passwords and OTPs? +

No. Whenever an input field is marked as a password, PIN, or OTP, Monolog automatically enters Protected Input Mode. In this state, text is transmitted directly to the host app through Android’s native InputConnection, no text is ever stored in memory or Room DB, predictions are disabled, and voice/AI features are blocked.

Does Vox Voice Mode listen to my conversations in the background? +

Absolutely not. Monolog does not possess background audio listening services, hotword wake engines, or passive ambient sound monitoring. The Android microphone is engaged exclusively while you hold the microphone key or tap Vox, and disengages the instant you release or stop recording.

Is my personal writing used to train AI models? +

No. On-device Gemma AI models run locally on your phone and do not transmit training weights back to any server. Furthermore, explicit cloud queries handled through Firebase AI Logic and Gemini 1.5 Flash are processed under strict commercial terms that prohibit using customer queries for training foundation models.

Can Monolog read incoming messages from my friends on WhatsApp or Signal? +

No. Android’s Input Method architecture only permits an IME to interact with the active text input field. Monolog cannot inspect incoming chat notifications, chat histories, or messages received from third parties. It captures only "your side of the day"—the text you draft or choose to retain.
